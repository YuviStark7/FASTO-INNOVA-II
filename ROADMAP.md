### Requested directly by Yuvi — 2026-08-27 (not from the queue)

**R4. [S] Sharp backdrops, and a cross-fade between them.** Three things. (1) **The blur was resolution, not compression.** The rotating photos were 2048×857 while `hero-farm.png` beside them was 2939×1690, so on a 3440-wide monitor the backdrops were being stretched about 1.7× and nothing else was — which is what made them look soft. Yuvi supplied his own 3440×1440 copies; they arrived as `Background 1.jpg`…`Background 6.jpg`, which is not what the app loads, so they were copied byte-for-byte onto `bg-1.jpg`…`bg-6.jpg` with no re-encoding. The duplicates are in `.gitignore` and safe to delete. (2) **`hero-farm.png` → `hero-farm.jpg`**, same dimensions, 758 KB instead of 4.94 MB, mean per-pixel difference about 1/255. It is not only the split-second fallback behind the app shell — it is also the sign-in background — but it sits under a `rgba(10,6,6,.55)`→`.8` gradient in both places, so the compression is not visible. (3) **The photo now cross-fades over 900ms** instead of cutting, using two stacked layers in `#main`.

**This shipped broken the first time and had to be fixed the same day — worth reading if you ever touch this code.** Three separate mistakes, all of which a passing test suite failed to notice: (a) each incoming layer was given an ever-climbing z-index, which passed the scrim on the third swap and the topbar and screens on the fourth, so the backdrop covered the entire dashboard; (b) the outgoing layer was never hidden after its fade, so from the third swap onwards the "spare" layer was still fully opaque and the new photo appeared instantly — one fade, then cuts forever; (c) fixing those introduced a third: an edit left a stray comment-close marker between two CSS rules, and the browser silently swallowed the `.backdrop-layer` rule that followed it, so `opacity:0` never applied and the fade stopped happening altogether, with nothing reporting an error. **The root cause behind all three was the verification, not the code** — the original 23 checks drove a hand-written fake DOM with no real opacity, no real stacking and no real stylesheet, so they confirmed the code did what it was written to do rather than what a browser does with it.

*What is in place now so this cannot repeat quietly:* the two layers own z-index 0 and 1 and never move between them (two layers only ever need two values); the outgoing layer is hidden on a timer once the new photo is opaque, which is what frees it for reuse; and `settleBackdrop()` ends any fade still running before a new one starts, since you can leave and return to the Dashboard faster than 900ms. `qa_check.js` gained four dependency-free guards — CSS comment markers balanced and none stray, braces balanced, the backdrop stacking order (layers 0/1 < scrim 2 < content 3) read from *comment-stripped* CSS so a rule swallowed by a runaway comment reads as missing, and the fade length in the CSS matching `BACKDROP_FADE_MS` in the JS. New optional `test_backdrop.js` (39 checks) drives the real `showBackdrop`/`rotateBackdrop` against the real stylesheet in jsdom and reads back *computed* opacity and z-index, so the cascade decides the answers; it needs `npm install jsdom` once and skips cleanly with a message if that is missing. Re-introducing each bug one at a time fails it by 9, 18 and 20 checks respectively, and two of the three also fail `qa_check.js`. *What still needs eyes:* jsdom has no transitions, so it only sees the state either side of a swap, never the dissolve itself — the mid-fade frame was checked separately in a real browser. Files: `js/app.js`, `css/app.css`, `index.html`, `qa_check.js`, `test_backdrop.js` (new), `assets/hero-farm.jpg` (new), `assets/Backgrounds/bg-1…6.jpg`, `.gitignore`.

8. **[M] Edit a captured profile.** — shipped 2026-08-28. An **Edit details** button now sits at the end of a finished conversation and next to your farm's pills in the "Why these buyers?" sheet. It opens a form holding everything Fasto took from the chat — name, village, distance, organic status, every product with its own quantity, and the months you can supply — with products you can add to and remove, and months you tap on and off. Saved with the same three database methods the original capture uses, so **no new table and no new column**. Until today a number Brain 1 slightly misheard was permanent unless you started the whole interview again.

*Three judgement calls worth knowing, because they are the difference between this and a plain form:*

**(a) The scores are recalculated; the written notes are not.** Fasto's ranking is arithmetic, so it is simply worked out again from your new numbers the moment you save — free, and always right. Brain 2's *written* sentences ("they buy 80 kg of tomatoes a week") were composed from the old figures and cannot be regenerated without another AI call, so they are marked stale and hidden, with a line saying why. Showing them would mean showing a description of a farm that no longer exists.

**(b) The outreach draft in Clients is never rewritten, only flagged.** It is the one thing in this app a real buyer ever reads, and you may already have sent it. After a correction the thread carries "⚠ You corrected your farm details after this was written — check the figures before you send it", and the toast on saving says the same thing. A draft already marked as sent is deliberately *not* flagged: you can't unsend it, so the warning would only worry you.

**(c) When the Guardian changes one of your numbers, the panel stays open and says so.** It still caps a quantity that is too large for a small farm at 5000 kg/week and assumes 8 km when a distance can't be read. Those corrections used to only exist in the console. Now the form redraws showing what was actually stored, with an amber "Saved. Fasto adjusted one thing on the way through: …" above the fields, rather than a toast that fades before you have read it.

*Smaller decisions:* the category and organic fields are dropdowns rather than text boxes, so nothing can be typed that the Guardian would then silently rewrite; a blank distance box is left off the profile entirely instead of being sent as `null`, because `Number(null)` is 0 and that would store a farm sitting in the middle of Cassino and quietly improve its distance score; the product list is only rewritten when the products actually changed, since saving them is a delete-then-insert and a pointless one is a real window in which a chat could lose them; clearing your name on one conversation does not wipe it from your account; and the sheet closes on the X, the backdrop or Escape but never on a stray click inside it, exactly like the logistics form.

**Verified** with 47 new tests added to `test_data_layer.js` (117 total, was 70) covering what is written and — as much — what is deliberately *not* written, plus a scratch jsdom harness of 45 checks driving the real form and the real stylesheets, reading back computed styles rather than trusting the code, with the mobile layout resolved through postcss at 390px since jsdom ignores `@media` entirely. **Proof they aren't passing for free:** 20 realistic regressions were put back in one at a time — the re-score skipped, stale notes left on show, a sent draft flagged, the Guardian's corrections discarded, a client-only chat id sent to Postgres, the `<select>` dropped out of the CSS rule that styles it, the mobile column override removed — and all 20 were caught. `test_engine.js` 19/19 and `qa_check.js` PASS. *What still wants your eyes:* jsdom has no real layout engine, so it can confirm which CSS rule wins but not that the result looks right — open a finished chat and press Edit details once. *Known limitations:* the "this draft is out of date" warning lives in the session only, so it is gone after a reload (persisting it needs a column on `outreach` — your call); and if the product save fails, the amber "Not saved" chip is the only sign, as everywhere else in the app. Files: `index.html`, `css/app.css`, `js/app.js`, `test_data_layer.js`, `README.md`.

3. **[S] Friendlier failure handling.** — shipped 2026-08-23. Every background save to Supabase (messages, profile, products, name, chat progress, matches, outreach drafts, "mark as sent") now goes through one `bgSave()` wrapper that reports failures in plain language instead of only to the console. **This turned out to fix a real bug, not just add messages:** Supabase *resolves* with `{ error }` rather than rejecting, so the old `.catch(console.error)` handlers never fired at all for the failures that actually matter — a row-level-security refusal, a constraint violation, an expired session. Those were being swallowed completely; only a hard network throw ever reached a handler. `bgSave()` checks both shapes. The messaging is deliberately restrained: failures that land together (a dropped connection usually kills the chat update, the products and the name in the same instant) are grouped into one sentence rather than three toasts fighting over one element, repeats are throttled to roughly one every 30s so a long offline stretch doesn't interrupt every few seconds, and an amber "Not saved" chip in the header persists after the toast fades — clickable for a recap, and it clears itself as soon as a write gets through again. Signing out no longer silently pretends to succeed: if the session survives, it says so before reloading, since the reload would otherwise walk straight back in. *Judgement calls worth knowing:* (a) the header chip is a new UI element, slightly beyond the item's literal "route through toast()" wording — added because a toast that fades leaves a farmer with no way to know their work isn't being saved; styled with the existing `--warn` token and glass-chip shape, amber not red, because nothing is lost within the session. (b) The boot-time session check is deliberately left console-only — it falls through to the sign-in card, which is the correct outcome, so a warning there would be noise. Verified with a throwaway sandbox harness covering the resolved-`{error}` path, thrown rejections, burst grouping, throttling, and the chip clearing (kept in scratch, not shipped). Files: `js/app.js`, `index.html`, `css/app.css`.
